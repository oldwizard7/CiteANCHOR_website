Abstract

Hallucinated citations make it harder to trace sources and verify the evidence behind scientific claims. Detecting them is difficult because bibliographic records can be incomplete or differ across source types and publication versions. A plausible match alone neither validates the citation nor establishes its underlying source. We introduce CiteResolve, a benchmark of 423 real-world hallucinated citations annotated for source recoverability. We further propose CiteANCHOR, a source-aware grounding framework that adapts retrieval and field-level verification to each source type and separately determines citation validity and whether a unique source can be recovered. On an existing detection benchmark, CiteANCHOR achieves 0.841 F1 with GPT-5.6 Luna and 0.784 with an open-weight backbone, outperforming the baseline with the same backbones by 7.9 and 36.8 points. On CiteResolve, it achieves 74.7% and 70.7% end-to-end task success, outperforming the corresponding web search baselines by 16.3 and 65.3 percentage points.

The CiteResolve Benchmark

Automated reference checks are already used at major conferences, with flagged references passed to human reviewers. For such screening to be useful, a system must explain why a citation is flagged and provide source records that allow reviewers to check its decision. Two challenges arise.

Interpreting heterogeneous source evidence

Papers, books, and web resources differ in how they can be retrieved and which fields identify them. A valid citation may omit a field present in a database record, while an invalid citation may match a record that omits the erroneous field. Detection needs source-aware interpretation that separates genuine contradictions from missing information and legitimate publication variants.

Separating citation errors from source identity

A citation with incorrect authors may still refer to an identifiable paper, whereas one with a fabricated title may have no real source at all. Evidence that establishes an error does not necessarily establish a replacement. A reliable system must decide whether a citation is wrong and, separately, whether its work can be uniquely identified, and abstain when it cannot.

CiteResolve makes this distinction measurable. Building on the Fake subset of the CiteAudit real-world test set, we annotate whether each hallucinated citation can be traced to a unique real work (Recoverable, with a verified corrected citation) or not (Unrecoverable, target None). Systems receive only the citation string and must decide whether it is hallucinated and, if so, return a uniquely supported source or None. Predicting Real on this subset always counts as a failure, so missed detections are penalized in the end-to-end score.

Source-Aware Grounding with CiteANCHOR

CiteANCHOR interprets retrieved records using source-specific criteria for citation verification and source resolution. Its central mechanism is evidence decomposition: individual bibliographic fields are checked before separate decisions are made about citation validity and source identity, so that a matching field does not validate the entire citation and an erroneous field does not automatically rule out its source. A chain-of-source strategy connects three modules that share the retrieved records:

  • Source discovery extracts title, authors, identifiers, venue, and year, determines whether the citation refers to a paper, book, or web resource, and retrieves records from cached and local resources first, then identifiers and structured bibliographic services (Crossref, OpenAlex, arXiv, Semantic Scholar, Europe PMC, Google Books, DataCite), and only then from Google Search and Google Scholar.
  • Evidence verification compares each field against the retrieved records with deterministic checks that distinguish contradictions from missing information and legitimate publication variants; an LLM judge handles only the comparisons these checks do not settle.
  • Source resolution reuses the collected evidence to recover the underlying work when exactly one record is supported, adds at most one targeted follow-up search when a detected error still has no supported source, and otherwise returns None.

The same retrieval rules and verification thresholds apply to both backbones we evaluate: the proprietary GPT-5.6 Luna and the open-weight OpenResearcher-30B-A3B, which supports local inference for confidential submissions.

Source-aware grounding improves both precision and recall over CiteAudit with the same backbone. With GPT-5.6 Luna, F1 rises from 0.762 to 0.841 (+7.9), with precision 0.875 vs. 0.751 and recall 0.809 vs. 0.773.
The gain is largest with the open-weight backbone. With OpenResearcher-30B-A3B, F1 rises from 0.416 to 0.784: false positives fall from 379 to 128 and missed hallucinated citations from 245 to 83. Deterministic field checks leave the backbone a narrow role, so the result depends less on which model fills it.

Web Search proposes more sources; CiteANCHOR proposes the right ones and knows when to stop. With GPT-5.6 Luna, Web Search names a source for 85.3% of recoverable citations against 65.9% for CiteANCHOR, but CiteANCHOR's proposals are more accurate (95.2% vs. 90.2%) and it correctly withholds a correction on 92.4% of unrecoverable citations against 31.0%. The result is 74.7% task success, 16.3 points above Web Search.
Web access alone does not make an open-weight backbone a reliable resolver. With OpenResearcher-30B-A3B, CiteANCHOR is best on all four metrics and reaches 70.7% task success, against 5.4% for Web Search and 3.3% for Direct Prompting: the baseline tends to copy the cited title and author list back as the answer, while CiteANCHOR reads authors and source from the retrieved records.

Ablation Study

With GPT-5.6 Luna, we examine three design choices: evidence decomposition, complementary retrieval sources, and source-type adaptation. Each variant is evaluated on detection (CiteAudit F1) and on end-to-end resolution (CiteResolve task success).

Table 4: Ablations with GPT-5.6 Luna. w/o Chain replaces staged verification and resolution with one LLM judgment over the same retrieved records. w/o Search Engines disables Google and Google Scholar searches. w/o Structured APIs removes bibliographic APIs while retaining search engines and cited webpages. w/o Type Adaptation uses generic retrieval and verification rules for all source types.

Evidence decomposition matters even with the retrieved evidence held fixed. Replacing the staged procedure with a single judgment over the same records lowers detection F1 by 19.8 points and resolution success by 15.4 points: a single judgment answers more often and is wrong more often, especially on unrecoverable citations.
Search engines and structured bibliographic records play complementary roles. Removing search engines mainly hurts detection (F1 0.841 → 0.734), while removing structured APIs mainly hurts resolution (success 74.7 → 53.2).
Source-type adaptation avoids losses on every kind of work. Generic rules reduce F1 by 8.0 points and success by 7.8 points; they flag far more real books and web resources, while paper-specific rules applied to everything would flag real web resources instead.
